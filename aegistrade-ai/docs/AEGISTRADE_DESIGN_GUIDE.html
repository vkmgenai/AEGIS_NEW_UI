AegisTrade AI: how the project is designed and why

AegisTrade is a research platform that tests one capstone question: does a supervisor-led team of specialists produce better grounded decisions than one agent given the same historical case, read tools, model family and call ceiling? A deterministic C0 flow remains the no-model reference. The project replays past NSE daily prices, never connects to a broker, and records every decision so it can be checked afterwards.

The idea in four sentences

  1. Code finds the trade signal. Indicators such as moving averages and RSI are calculated in Python on completed daily bars.
  2. Agents check the evidence. In the AI flows, language-model agents read dated company disclosures and the project's policy passages, then say whether the signal should go ahead and cite what they read.
  3. Code controls the money. Quantity, fees, stops, profit targets and portfolio limits are always calculated by tested Python, never by a model.
  4. Everything is recorded. Each decision, tool call and fill is saved, so a reviewer can compare the AI flows with the no-AI baseline on the same data.

The most useful thing to keep in mind while reading the code: the language model is allowed to interpret evidence and explain. It is never allowed to do arithmetic, size a position or place an order.

Walkthrough

  1. The reviewer picks a stock universe, a date range, capital and a flow in the dashboard. For AI flows they also pick the provider and tick a consent box, because model calls use a paid allowance.
  2. The API checks the reviewer token, validates every setting with typed models, and starts the run in the background so the screen can show progress.
  3. For each trading day the code builds a locked case: the stock, its closing price, its indicators and a cutoff time. Nothing dated after the cutoff can enter the case.
  4. The case goes to C0, C1 or C2. C0 decides with rules alone. C1 and C2 ask agents to check the evidence first.
  5. Agents fetch facts only through MCP tools, and their text is generated by whichever provider is selected.
  6. Code validates what the agents returned, then the risk engine sizes the trade and simulates the fill on the next session's open.
  7. The run is checkpointed after each step, so a paused run can resume, and the ledgers feed the evaluation reports.

The three flows: C0, C1 and C2

The formal capstone comparison is C1 versus C2: the same evidence-review task, case, read tools, model family and call ceiling, with orchestration as the intended difference. C0 is retained as a deterministic, zero-model reference rather than being mislabeled as the single-agent baseline.

Supervisor (plan step)

A LangGraph node written in code, not a model call. It creates a typed plan and keeps the shared state. LangGraph, not the model, decides which agent runs next, so the order of work cannot be changed by a clever prompt.

Market specialist

Calls the market tools to get the price snapshot and the company's dated disclosures. Reports the market regime and whether any adverse event was found.

Strategy specialist

Searches the policy corpus, selects one approved strategy and must cite the passage IDs that support it.

Critic

Has its own tool access and checks the earlier answers against the sources. It is the reason C2 differs from C1.

Code validation

Even after the critic accepts, Python checks that cited passages exist, quotes appear in the source text, dates are before the cutoff and the route is allowed. Hard validation and safety failures cannot be overridden.

Human evidence override

Only an evidence-insufficient block with a positive technical BUY/SELL candidate can pause for a recorded decision. The screen shows relevant prices, the bell reports pending work, and the same completed research is reused without another model call.

Linked lifecycle

If a person overrides a blocked BUY, that position is tagged. Its later SELL review, fill and attributed P&L remain linked in a separate ledger so the intervention can be judged as a complete outcome and considered for a reviewed lesson.

Holding reviews

Open positions are reviewed on a schedule and when new disclosures appear. Protective stops and hard safety exits execute by code and never wait for human approval.

How one trade is simulated

The backtester is deliberately strict about time. A decision can only use information that existed when it was made.

Day T · after closeSignal and researchIndicators are calculated on the completed bar. In C1 and C2 the agents research the candidate.
Day T · after closeSizingWhole shares only. Risk per trade is 1% of equity (0.5% for breakouts), sized from the stop distance. At most 20% of equity in one stock, 4 positions and a 3% daily-loss limit. A stop price is set, by default 2 × ATR below entry (2.5 × for breakouts).
Day T+1 · openFillThe order fills at the next session's opening price, with slippage and the fixed NSE delivery charges (STT, stamp duty on buys, exchange and SEBI fees, GST; brokerage is zero).
Each later dayProtectionThe stop, an optional trailing stop and a profit target (8% by default in the backtest and comparison pages) are checked by code. Strategy exit rules and cited adverse news can also close the position.
End of periodMark to marketOpen holdings are valued at the last close. They are not force-sold, so the result is not distorted by an artificial final sale.

Ideas worth learning from this project

Point-in-time data

Every fact carries the time it became available. A backtest that uses later information looks brilliant and is worthless. This is called look-ahead bias.

Grounding and citation

An agent's claim must point to a passage or document that code can find. This is how retrieval-augmented generation reduces invented answers.

Hybrid retrieval

Keyword search finds exact terms such as a rule number. Embedding search finds similar meaning. Combining and reranking both gives better passages than either alone.

Least privilege for agents

Each agent gets only the read tools it needs. The one write tool is held back behind human approval.

Typed hand-offs

Agents pass structured objects with fixed fields, not free text. A missing or wrong field is caught at once.

Ablation

To know whether orchestration helps, compare C1 and C2 on the same cases, tools, model family and ceiling. C0 remains a useful deterministic reference, but it does not replace the required single-agent baseline.

Checkpoint and resume

Long agent runs fail in the middle. Saving state after each step, and refusing to resume if settings changed, keeps results valid.

Fail closed

When a provider fails or evidence cannot be verified, the system blocks or pauses. It never falls back silently to another model or assumes the answer.

Suggested order for reading the code

  1. aegistrade/strategies.py then aegistrade/engine.py. Understand a C0 backtest first. No AI is involved.
  2. aegistrade/safety.py and aegistrade/execution_policy.py. See how risk limits and stops are enforced.
  3. knowledge/corpus.jsonl and aegistrade/knowledge.py. Read a few passages, then see how search works.
  4. mcp_servers/market_server.py and knowledge_server.py. These are the tools agents call.
  5. config/agents.json then aegistrade/agentic.py. Read the role instructions, then the graph that runs them.
  6. aegistrade/llm_backend.py. How one interface serves three providers.
  7. aegistrade/research_gate.py. The checks applied to agent output.
  8. aegistrade/c2_portfolio.py. The full loop that ties everything together over many days.
  9. app/api.py and app/ui.py last. They expose what you have already understood.

Try it yourself

  • In Strategy Backtests, open the C0 reference or C2 portfolio tile. Run a short period, follow live progress and read the trade and decision ledgers line by line.
  • In Policy Knowledge, search for "stop loss" and see which passages come back and why.

  • Run .venv/bin/python -m pytest -q and open one test file next to the module it covers.

Limits you should know about

  • Simulation only. There is no broker connection and results are not a forecast.
  • No demonstrated trading edge from the agents yet. In the comparison runs done so far on the related build of this project, the AI flows did not reliably beat the technical baseline, and all versions trailed simply buying and holding. What the agents add today is a cited, checkable evidence review.
  • Daily bars and unadjusted prices. Intraday moves are not modelled, and corporate actions such as splits are handled by keeping affected stocks out, not by adjusting prices.
  • Evidence coverage is uneven. Some stocks and dates have few filings available, and the system reports that as incomplete coverage.
  • Survivorship bias. The stock lists were chosen recently, so they contain companies that did well enough to be on the list.
  • Model output varies. Two runs with the same settings can differ slightly, and each provider behaves differently.
